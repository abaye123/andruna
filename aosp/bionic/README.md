# aosp/bionic

Andruna's sources for the guest bionic: AOSP's real bionic built as
Android ELF (`<arch>-linux-android`, ADR 0013) and loaded by
andruna-linker in a Windows process. The build is
[`../modules/bionic.cmake`](../modules/bionic.cmake), driven by
[`../tools/build_guest.py`](../tools/build_guest.py) (step `bionic`).

## System calls

bionic is unchanged except where it executes system call instructions.

- **Stubs.** The stubs of `libc/SYSCALLS.TXT` are generated by
  [`../tools/gensyscalls_andruna.py`](../tools/gensyscalls_andruna.py),
  which runs bionic's own `gensyscalls.py` with other per-architecture
  templates: instead of `syscall` / `svc #0` each stub calls the host
  function `__andruna_syscall`.
- **Convention of `__andruna_syscall`.** Arguments in the C argument
  registers (x86_64: `rdi rsi rdx rcx r8 r9`, so the fourth argument is
  not moved to `r10`; arm64: `x0`-`x5`), the number in `rax` (x86_64) or
  `x8` (arm64); the result in `rax` / `x0` is the raw kernel value
  (-4095..-1 is `-errno`); everything else as a normal System V / AAPCS64
  call. The stub then sets bionic's `errno` exactly as the upstream stub.
  andruna-linker forwards the calls to andruna-lx, or handles the few that
  belong to the loader (threads, the thread pointer, process exit).
- **Replaced assembler files** (left out of the build, replaced here):
  `syscall()` ([`arch-x86_64/syscall.S`](arch-x86_64/syscall.S),
  [`arch-arm64/syscall.S`](arch-arm64/syscall.S)), and in
  [`andruna_threads.cpp`](andruna_threads.cpp) `__bionic_clone` (the host
  starts a Windows thread on bionic's stack and TLS in bionic's
  `__start_thread`; `__andruna_clone_thread`), `__bionic_clone3` (fails
  with `ENOSYS`), `_exit_with_stack_teardown` (the host unmaps the stack
  after leaving it; `__andruna_exit_with_stack_teardown`) and `vfork`
  (fails with `ENOSYS`: a Windows process cannot fork).
- **Patches** ([`../../patches/bionic`](../../patches/bionic), all gated on
  `ANDRUNA`): `__restore_rt` returns through the host on x86_64 (0005);
  arm64 `__set_tls` calls `__andruna_set_tls` (0003); no shadow call stack
  on arm64, where x18 is the TEB (0004); `longjmp` leaves x18 alone on
  arm64 (0006). 0001 and 0002 belong to the Windows-target fallback build
  and are inactive here.

`ANDRUNA` is defined for bionic's own sources only.

## Host functions

[`host_symbols.txt`](host_symbols.txt) lists every name guest objects may
import from the host. The build turns it into `libandruna_host.so` (empty
functions); libraries link against it as NDK code links against stub
libraries, and andruna-linker binds the names to its host table without
loading the file. Besides the system call entry these are the `__loader_*`
functions of `libdl.so` (the `dlopen` family) and `__icu4x_bionic_*`, the
Unicode properties that Android computes with ICU4X in Rust inside
`libc.so`.

## The bridge `ld-android.so`

bionic's linker contains a private copy of libc that sets up the main
thread and owns the loader's shared globals (`__libc_shared_globals`: the
static TLS layout and module table that `libc.so` uses). andruna-linker is
Rust, so that part is [`ld_android_bridge.cpp`](ld_android_bridge.cpp),
linked like Android's linker with the static parts of libc
(`libc_nomalloc` plus the dynamic string dispatch, with
`--exclude-libs=ALL`), its own allocator
([`bridge_malloc.cpp`](bridge_malloc.cpp), bionic's `BionicAllocator` as
in the linker) and, on arm64, bionic's dynamic TLSDESC resolver. Its
version script ([`ld_android_bridge.map.txt`](ld_android_bridge.map.txt))
exports only `__loader_shared_globals` and `__andruna_bridge_*`.

## What else differs from Android's libc

- Allocator: scudo, Android's default, from `external/scudo`.
- Unwinder: LLVM's libunwind from the llvm-project tree of the compiler's
  tag is linked into `libc.so` and exported (Android's
  `libunwind-exported`), so C++ exceptions work in every guest object.
- Not built: bionic's Rust pieces. `libicu4x_bionic` is replaced by host
  functions; `liblibc_alloc_rust` and `libbionic_panic_abort` only serve
  Rust code inside libc, and there is none here.
- `generated_android_ids.h` is produced by
  [`../tools/gen_android_ids.py`](../tools/gen_android_ids.py) from
  libcutils' `android_filesystem_config.h`; ids whose names exceed bionic's
  16 characters are left out (Android's generator renames them).
- Source lists come from the Android.bp files through
  [`../tools/blueprint.py`](../tools/blueprint.py); warnings are not
  errors (`-w`), since the modules' `-Werror` targets Android's compiler.

## bionic's own tests

`build_guest.py tests` builds `bionic_tests` from a subset of
`bionic/tests` (see [`../guest/bionic_tests.cmake`](../guest/bionic_tests.cmake)
for the list), with gtest's own main: bionic's isolating runner forks for
every test, which Windows cannot do. Left out for now: tests that need
fork/exec, signals, sockets, `/proc`, ptrace, or the test libraries of
`bionic/tests/libs` (dlfcn, dlext, elftls, ifunc, ...).
