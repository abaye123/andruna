# S2 result: shared boot image and garbage collection

**Status:** in progress, round 1 (before ART runs). Boot image mapping and
the Windows primitives for a `userfaultfd` substitute are measured with
synthetic data; ART itself is round 2.
**Code:** [`spikes/s2/`](../../../spikes/s2/) (standalone Cargo project, throwaway).

## Question

Can the boot image be mapped from one section into several processes at the
same address, and which garbage collector works well without `userfaultfd`?

## Summary

- **Boot image: yes.** One section, mapped read-only at a fixed address into
  a placeholder in every process, with copy-on-write only on the pages ART
  will dirty. Per process the image costs only the dirtied pages plus page
  tables: **+4.6 MiB private commit and +4.0 MiB private working set for a
  320 MiB image with 4 MiB dirtied**, the same in an AppContainer.
  Reserve + map takes **40-65 µs**. The fixed range was free in **200 of 200**
  launches (50 in an AppContainer), both while suspended and at `main`.
- **Two traps found.** Mapping the whole view copy-on-write charges the whole
  view to the process commit (**+320.6 MiB per process**), so only the dirty
  range may be `PAGE_WRITECOPY`. Relocating the image (when the fixed address
  is unavailable) costs **~220 ms and +320 MiB private per process**.
- **First touch is not free.** Even with every page resident, each 4 KiB
  page costs **1.1-1.5 µs** on first access in each process (soft fault);
  touching all of a 320 MiB image took 87-108 ms. `PrefetchVirtualMemory`
  does not help. What matters is how much of the real image ART touches.
- **GC: use CC now, keep CMC's stop-the-world fallback as the fallback.**
  android-17's runtime picks concurrent copying (CC, Baker read barriers)
  automatically when `userfaultfd` is missing, if ART is built with read
  barriers. CC needs only `mmap`/`mprotect`/`madvise` and thread checkpoints.
  Andruna's current ART build (no read barriers) always uses CMC, which
  without `userfaultfd` compacts in a stop-the-world pause.
- **A `userfaultfd` substitute works but is not cheap.** The prototype
  (alias view + `VirtualProtect` + vectored exception handler) was correct
  (0 bad pages over all runs). A mutator fault costs **5.5 µs p50 on one thread
  and 10-11 µs with 2-7 threads**, with millisecond tails. The pause-time
  `mremap` substitute costs **~10 ms per 64 MiB of resident heap**, mostly
  `UnmapViewOfFile` at ~0.6 µs per page. That removes most of CMC's
  pause-time advantage unless the flip is redesigned (see GC section).

## Machine and method

- Intel Core Ultra 7 258V (4 P + 4 LP-E cores, no SMT), 32 GB, Windows 11 Pro
  build 26300. **On battery, Balanced power plan, busy laptop**: total CPU load
  was 93% (other workloads) when the boot image runs started and 26% before
  the GC run. Tails (p99 and above) are dominated by this and must be
  measured again on the reference PC.
- Rust 1.92.0, `x86_64-pc-windows-msvc`, release build. Timing with
  `Instant` (QPC).
- Memory numbers come from the broker, measured on every child while all
  children are alive: `QueryWorkingSetEx` per page of the image range
  (valid, shared, private), `GetProcessMemoryInfo` with
  `PROCESS_MEMORY_COUNTERS_EX2` (working set, private working set, private
  commit), `GetPerformanceInfo` for system commit.

## 1. Boot image mapping

### What was built

- **Synthetic boot image**: 320 MiB of 256-byte objects. Each object holds
  absolute 32-bit references (self, next, class) that are valid only at the
  fixed base `0x60000000`, as ART's compressed heap references are. Children
  check the self reference of every page and follow 200 000 `next` links.
- **Broker** builds one section: pagefile-backed (`SEC_COMMIT`, filled
  through a temporary view) or file-backed (a 320 MiB file opened read-only,
  section `PAGE_READONLY`).
- **Children**, 24 per run plus one baseline child that maps nothing; two
  children per 24-child run are in a fresh AppContainer with no capabilities.
  Two mapping modes:
  - `self`: at the start of `main`, `VirtualAlloc2(MEM_RESERVE |
    MEM_RESERVE_PLACEHOLDER)` at the base, then `MapViewOfFile3(...,
    MEM_REPLACE_PLACEHOLDER)` using an inherited **read-only** section handle
    (`SECTION_MAP_READ | SECTION_QUERY`).
  - `inject`: the broker creates the child suspended, then reserves the
    placeholder and maps the view **into the child** (`VirtualAlloc2` and
    `MapViewOfFile3` with the child's process handle, `VirtualProtectEx` for
    the copy-on-write range), then resumes it. The child gets no section
    handle at all. This is option 2 of
    [security: warm processes](../../spec/04-security.md#warm-processes-and-appcontainer).
- **Copy-on-write**: `--cow part` maps the view `PAGE_READONLY` and changes
  only the range ART would dirty to `PAGE_WRITECOPY`; `--cow all` maps the
  whole view `PAGE_WRITECOPY`. Each child then writes one word in each of
  1024 pages (4 MiB, a stand-in for class statics and other dirty objects
  that ART's image writer groups together).

### Results (24 children, 320 MiB image, 4 MiB dirtied, median [min-max])

| | pagefile, self | pagefile, inject | file, self |
| --- | ---: | ---: | ---: |
| Spawn to ready (includes touching every page) | 136.7 ms [128.5-164.1] | 113.2 ms [107.3-149.3] | 118.7 ms [112.5-143.3] |
| Baseline child, no image, spawn to ready | 23.7 ms | (same binary) | 27.5 ms |
| Reserve + map (+ protect dirty range) | 62 µs [54-123] | 65 µs [50-135] | 40 µs [36-79] |
| Touch every page (81 920 pages, all resident) | 107.9 ms [101.2-135.8] | 91.6 ms [87.8-102.2] | 93.8 ms [90.7-112.3] |
| Per page | 1.32 µs | 1.12 µs | 1.14 µs |
| Write to 1024 copy-on-write pages | 2.53 ms | 1.91 ms | 2.21 ms |
| Image working set / shared / private | 320.0 / 316.0 / 4.0 MiB | same | same |
| Private working set vs baseline child | +4.0 MiB | +4.0 MiB | +4.0 MiB |
| Private commit vs baseline child | +4.6 MiB | +4.6 MiB | +4.6 MiB |
| Bad references | 0 | 0 | 0 |
| AppContainer children | same numbers as the others | same | same |

- Every child, AppContainer or not, saw identical memory numbers: 316 MiB of
  the image shared, only the 4 MiB written private. The extra 0.6 MiB of
  commit over the dirty pages is the page tables for a 320 MiB view
  (81 920 PTEs x 8 bytes = 0.63 MiB).
- The pagefile-backed section is charged to system commit once, by the
  broker (+290 to +352 MiB measured; noisy because of other activity). The
  file-backed section charges no commit: its clean pages can be dropped and
  read back from the file. Children cost the same in both.
- A child holding the read-only handle **cannot** map the section writable:
  `MapViewOfFile3(PAGE_READWRITE)` fails with `ERROR_ACCESS_DENIED` (5), in
  and out of the AppContainer. A `PAGE_WRITECOPY` view works with that handle,
  so a process can change its own copy but never the shared image.
- `VirtualProtect` to `PAGE_WRITECOPY` works at 4 KiB granularity inside the
  view (checked with a 1001-page range: 3.9 MiB private).

### Copy-on-write for the whole view: the commit trap

| 12 children | `--cow part` | `--cow all` |
| --- | ---: | ---: |
| Private commit vs baseline, per child | +4.6 MiB | **+320.6 MiB** |
| Private working set vs baseline | +4.0 MiB | +4.0 MiB |
| System commit, all 12 children | about +0.1 GiB | **+3.8 GiB** |

Windows charges commit for every page of a `PAGE_WRITECOPY` view when it is
mapped, because each page may become private. Ten apps would charge 3.2 GB
of commit for pages they never write. **The view must be `PAGE_READONLY`
with only the dirty range `PAGE_WRITECOPY`**, which means the image layout
must keep the pages ART writes together (ART's image writer already groups
dirty objects; round 2 checks which pages the real image dirties).

### Fixed address: ASLR and the fallback

`s2 aslr --runs 200`: 200 launches of a probe process, every fourth one in an
AppContainer, recording every allocation below 4 GiB while the process is
suspended (from the broker, `VirtualQueryEx`) and again at `main` entry.

| | result |
| --- | --- |
| `0x60000000` + 320 MiB free while suspended | 200 / 200 |
| Same range free at `main` entry | 200 / 200 |
| Anything else below 4 GiB | only `KUSER_SHARED_DATA` at `0x7FFE0000`, in every launch |

With high-entropy ASLR, Windows places nothing of a 64-bit process below
4 GiB except `KUSER_SHARED_DATA` (fixed at `0x7FFE0000`). That has two
consequences:

- ART's default `ART_BASE_ADDRESS` (`0x70000000`, set in
  `aosp/modules/libartbase.cmake`) leaves only 255.9 MiB before
  `0x7FFE0000` for the boot image and its oat files. Andruna can move the
  base (it is a build define) or keep the image under that size.
- The probe is a small Rust executable. A real host process loads drivers
  (D3D, ANGLE) that could allocate low. The `inject` mode reserves the range
  before the child runs any code, so collisions cannot happen there; `self`
  at `main` entry is safe only before such DLLs load.

**Fallback when the address is taken** (`--force-reloc`: map elsewhere below
4 GiB with `MEM_ADDRESS_REQUIREMENTS` and patch every reference, as ART
relocates an image it cannot map at its address):

| | fixed address | relocated |
| --- | ---: | ---: |
| Spawn to ready | 127.6 ms | 244-248 ms |
| Relocation (patch 3 references in each of 1.3 M objects) | - | 218-227 ms |
| Image private working set | 4.0 MiB | **320.0 MiB** |
| Private commit vs baseline | +4.6 MiB | **+320.6 MiB** |

Relocation makes the whole image private, so it must stay a rare, last-resort
path. It never happened in 200 launches. Searching below 4 GiB
(`MEM_ADDRESS_REQUIREMENTS`) works for the fallback and is also what lx needs
for `MAP_32BIT` and ART's low-4 GiB heap (currently `ENOMEM` in
`crates/andruna-lx/src/mem.rs`).

### First-touch cost and prefetch

Every child touched every page; all pages were already resident (the broker
or earlier children had touched them). Each page still costs a soft fault of
**1.1-1.5 µs** per process, the same for pagefile- and file-backed sections
(no fault-around was seen). `PrefetchVirtualMemory` over the whole view took
28-39 ms and did not reduce the touch time (86 ms after it vs 89-108 ms
without), since it only reads pages into memory and does not map them.

So the cost of the boot image at start is about **1.3 µs per 4 KiB page that
ART touches**: 100 MiB touched is about 33 ms. Round 2 measures ART's real
touch set.

### 64 KiB alignment

- The view's base address and its offset in the section must be multiples of
  64 KiB (allocation granularity); the size is rounded up to 4 KiB pages.
  Placeholders can be split at 4 KiB, but views cannot start there.
- Inside a view, protection changes work at 4 KiB (verified above).
- So each separately mapped part of the boot image (each `.art` image and
  each oat file, if mapped as separate views) must start at a 64 KiB-aligned
  file offset and a 64 KiB-aligned address. Either dex2oat lays the image out
  with 64 KiB alignment (`ART_PAGE_SIZE_AGNOSTIC` is already set; whether
  dex2oat can be told to use 64 KiB alignment is for round 2), or the whole
  boot image set lives in one file mapped as one view.

### Recommendation for the boot image

1. sysd builds or opens the boot image **file** (read-only, in the install
   directory) and holds one file-backed section: no commit charge, pages
   reclaimable, kept in the page cache between runs.
2. sysd creates each host process **suspended**, reserves the placeholder,
   maps the view `PAGE_READONLY` and the dirty range `PAGE_WRITECOPY` into
   it, then resumes it. The app gets no handle to the section. lx records
   the view in its address-space table as a file mapping it does not own
   (`munmap` of it is refused, as for other memory lx does not own).
3. Never map the whole image `PAGE_WRITECOPY`.
4. Relocate only as a last resort; log it.

## 2. Garbage collection without `userfaultfd`

### Collectors in android-17 and what they need

Read from `art/runtime/gc/collector_type.h`, `cmdline/cmdline_types.h`,
`runtime/read_barrier_config.h`, `runtime/runtime.cc`, `runtime/gc/heap.cc`,
`runtime/gc/collector/mark_compact.cc`, `runtime/gc/space/region_space.cc`
and `build/art.go` at `android-17.0.0_r1`.

`-Xgc:` accepts `MS`, `CMS`, `SS`, `CC` and `CMC`, but the **build
configuration** decides what can run:

| Build (art.go) | `gUseReadBarrier` / `gUseUserfaultfd` | Collector that runs |
| --- | --- | --- |
| Read barriers on (`ART_USE_READ_BARRIER=1`, Baker; the art.go default when the product enables read barriers) | decided at startup by `ShouldUseUserfaultfd()` | CMC if `-Xgc:CMC` is on the command line (read from `/proc/self/cmdline`), or on an Android target when the `enable_uffd_gc` property says so **and** the kernel has `userfaultfd` with `UFFD_FEATURE_SIGBUS`; otherwise **CC** (runtime.cc forces the collector type to CC) |
| Read barriers forced (`ART_FORCE_USE_READ_BARRIER`) | constant: CC | CC |
| No read barriers, default GC CMC (**Andruna's current build**, `libartbase.cmake`) | constant: CMC | CMC; without `userfaultfd` it uses its stop-the-world fallback |
| No read barriers, default GC CMS or MS | constant: neither | CMS / MS (non-moving), background compaction by `HomogeneousSpaceCompact` |
| `ART_TEST_DEBUG_GC` | - | SS (testing only) |

What each needs from the kernel (that is, from lx):

| Collector | Kernel features | Pauses | Notes |
| --- | --- | --- | --- |
| **CMC, concurrent compaction** (device default) | `userfaultfd` with `UFFD_FEATURE_SIGBUS` (SIGBUS `BUS_ADRERR` on missing pages), ioctls `UFFDIO_API/REGISTER/UNREGISTER/COPY/ZEROPAGE`, optionally `UFFDIO_MOVE` and `MMAP_TRYLOCK`; `mremap(MREMAP_MAYMOVE \| MREMAP_FIXED \| MREMAP_DONTUNMAP)` (5.13+, else `MAP_FIXED_NOREPLACE` re-map); `madvise(MADV_DONTNEED)` | marking pauses + a short compaction pause (`KernelPreparation`: `mremap` of the moving space, register with uffd) | no read barrier in compiled code |
| **CMC, stop-the-world fallback** | `mmap`, `munmap`, `madvise`; probes `userfaultfd` and `mremap(MREMAP_DONTUNMAP)` at startup and falls back when either fails ("falling back to stop-the-world compaction"); also forced by `ro.dalvik.vm.force_cmc_stw_compaction` | marking concurrent (card table), **compaction of the whole moving space in a pause** | works on lx today if `userfaultfd` returns `ENOSYS` and `mremap` fails cleanly |
| **CC, concurrent copying** (generational) | `mmap`, `munmap`, `mprotect`, `madvise(MADV_DONTNEED)` (region clearing); thread checkpoints and flip (S1) | thread flip and checkpoint pauses, not proportional to heap size | Baker read barrier in all compiled code: boot image, AOT and JIT must be compiled for it; region space needs headroom for evacuation |
| **CMS / MS** | `mmap`, `madvise`, `mprotect` | remark pause (card scan); background compaction is stop-the-world | needs a separate non-read-barrier, non-CMC build; not the device configuration since CC; fragmentation |

### Prototype: a `userfaultfd` substitute on Windows

`s2 gc` models one CMC compaction cycle on a 64 MiB moving space:

- **`mremap(MREMAP_DONTUNMAP)` substitute (the pause):** the heap is a view
  of pagefile section S0 at a fixed placeholder H. Map a second view of S0
  elsewhere (the from-space F), unmap H keeping the placeholder
  (`UnmapViewOfFile2(MEM_PRESERVE_PLACEHOLDER)`), map a fresh section S1 at
  H, `VirtualProtect` it `PAGE_NOACCESS`, and map an alias view A of S1 that
  only the collector writes.
- **`UFFDIO_COPY` substitute:** compute the to-space page (copy 4 KiB and
  update every fourth word as a reference) into A, then `VirtualProtect` the
  page at H to read-write. Until then any access faults, so no mutator sees
  a partly filled page.
- **SIGBUS handler substitute:** a vectored exception handler claims the
  page (per-page state `empty -> busy -> done`), fills it or spins until the
  collector finishes it, and resumes the faulting instruction.
- The collector thread compacts pages in order, claiming runs of up to 16
  pages and unprotecting each run with one `VirtualProtect`.
- Every run checks every page afterwards: **0 bad pages in all runs.**

Results (64 MiB, 16 384 pages, median of 3 runs):

| Measurement | Result |
| --- | ---: |
| Stop-the-world copy + update into resident memory, 1 thread (lower bound for a STW compaction) | 6.9 ms = 9.0 GiB/s = 0.42 µs/page |
| Fault round trip, handler only unprotects (1 / 2 / 4 / 7 threads) | 4.9 / 6.0 / 8.4 / 18.9 µs per fault per thread; peak 0.48 M faults/s at 4 threads |
| Collector alone, fresh (demand-zero) to-space, batch 1 / 16 / 64 | 3.06 / 2.60 / 2.55 µs/page (1.25-1.50 GiB/s) |
| Collector alone, to-space pages already allocated, batch 1 / 16 | 1.09 / **0.54** µs/page (3.5 / 7.1 GiB/s) |
| Mutators only (every page filled in the handler), fault latency p50 / p99 (1 thread) | 5.5 / 8.9 µs |
| Same, 2 / 4 / 7 threads, p50 / p99 / p99.9 | 6.5 / 9.7 / 22 µs; 10.0 / 28 / 211 µs; 11.2 / 44 / 2978 µs |
| Concurrent: collector + 1 / 2 / 4 / 7 mutators (2 µs of work between touches), compaction time | 41 / 50 / 54 / 65 ms |
| Same, mutator fault latency p50 / p99 | 10.3-11.4 / 24-34 µs (p99.9 0.1-3.8 ms) |
| Pages filled by mutators in that run | 2 225 / 4 540 / 7 718 / 11 263 of 16 384 |
| **Flip in the pause** (alias F, unmap H, map S1, protect, alias A) | **10.2 ms**, of which `UnmapViewOfFile` of the resident heap view **9.6 ms** and `VirtualProtect` `NOACCESS` 0.5 ms |
| Freeing the from-space after compaction: `MEM_RESET` on the view / `DiscardVirtualMemory` / unmap + close | 7.6 / 8.4 / 10.2 ms per 32-64 MiB; both `MEM_RESET` and `DiscardVirtualMemory` work on a section view and drop the pages from the working set |
| Read-barrier fast path (flag test per reference load), pointer chase / independent scan | +1.1% / +13.8% per load |

What this says:

- Each primitive works and the protocol is correct, but **every protection
  change and every unmap costs about a microsecond per page**, and
  `VirtualProtect` scales badly past 4 threads (it serializes on the
  process's address-space lock).
- A fresh to-space costs 2.5 µs/page because each section page is
  demand-zero allocated on first write; recycling the previous cycle's pages
  as the next to-space brings it to 0.54 µs/page (Linux CMC does the same
  with `UFFDIO_MOVE`).
- **The pause is the problem.** Unmapping a resident view costs ~0.6 µs per
  page, so the flip of a 64 MiB heap takes ~10 ms, more than the 6.9 ms lower
  bound of compacting 64 MiB with everything stopped. A substitute worth
  having needs a different flip: for example a heap made of many small views
  flipped lazily on fault, or compacting in place with a side buffer for
  pages filled out of order. Both are substantial lx work.
- Mutator stalls of 5-11 µs per fault are acceptable at p50, but the
  millisecond p99.9 under contention (measured on a loaded machine) would
  show as jank.

### Pause-time estimate for a 64 MiB moving space

| Option | Pause per full compaction | Mutator cost | Work for Andruna |
| --- | --- | --- | --- |
| CMC, STW fallback (current build) | at least 7 ms (memcpy + update lower bound measured here); ART's per-object work (live-words bitmap, reference visiting) will make it several times that: to be measured in round 2 | none outside GC | none: lx returns `ENOSYS` for `userfaultfd` and fails `mremap(MREMAP_DONTUNMAP)` |
| CMC with emulated `userfaultfd` (this prototype) | ~10 ms flip (unmap-bound) + marking pauses | 5.5-11 µs per fault p50, ms tails; ~0.5-2.6 µs/page collector cost | large: uffd fd and ioctls, SIGBUS for registered ranges, `mremap` on section-backed anonymous memory, section-backed moving space in lx |
| **CC** (read-barrier build) | thread flip and checkpoints, not proportional to heap size | read-barrier fast path on every reference load (+1% to +14% per load here; real apps to be measured); evacuation headroom | build flag change; boot image, AOT and JIT compiled with read barriers; nothing extra in lx |
| CMS (non-moving build) | remark pause; STW compaction only in background | none | a third build configuration that devices no longer use; fragmentation |

### GC recommendation

1. **Build ART with Baker read barriers (`ART_USE_READ_BARRIER=1`,
   `ART_READ_BARRIER_TYPE_IS_BAKER=1`) so the runtime selects CC**, which is
   the collector android-17 itself falls back to when `userfaultfd` is
   missing and the one ART uses on host. It needs nothing from lx beyond
   what is already planned. dex2oat and the boot image must be built with the
   same setting. This changes `aosp/modules/libartbase.cmake` and is an
   ADR-level decision (proposed below).
2. Until then, the current build runs **CMC in its stop-the-world fallback**.
   That is a correct configuration for bring-up, with long pauses on large
   heaps. lx must make the probes fail cleanly: `userfaultfd` returns
   `ENOSYS`, `mremap(MREMAP_DONTUNMAP)` returns an error.
3. **Do not build a `userfaultfd` emulation now.** The measured flip cost
   (~10 ms per 64 MiB) removes most of its benefit. Revisit only if CC's
   read-barrier overhead on real apps turns out to be significant, and then
   with a redesigned flip.

### Proposed decision (for an ADR if accepted)

- **Status:** proposed by S2 round 1.
- **Context:** CMC, the device default, needs `userfaultfd` and
  `mremap(MREMAP_DONTUNMAP)`, which Windows does not have. Emulating them
  works but costs ~10 ms in the pause per 64 MiB of heap and microseconds
  per mutator fault.
- **Decision:** build ART with Baker read barriers; the runtime then selects
  CC because `userfaultfd` is missing. The boot image and all AOT code are
  compiled with read barriers.
- **Consequences:** pauses do not grow with heap size; every reference load
  in compiled code carries the read-barrier fast path; the heap needs
  evacuation headroom. The decision is confirmed or reverted by S2 round 2
  numbers on real apps.

## Not verified

- Nothing ran on ART: no real boot image, no real GC. All numbers are for
  synthetic data and the Windows primitives.
- Cold start: the boot image file was always in the page cache (it was just
  written); reading it from disk was not measured.
- Two processes creating their own sections on the same boot image file
  (instead of sysd handing out one section) should share pages through the
  file's cache; not measured.
- The `self` mode collision rate in a process that has loaded D3D, ANGLE and
  graphics drivers.
- Whether dex2oat can lay out the boot image with 64 KiB alignment.
- CC's pause times and read-barrier overhead in ART; the CMC fallback's real
  pause times.
- ARM64: everything here was measured on x64 only.
- Numbers on a quiet machine on mains power.

## What to measure once ART runs (round 2)

1. **Boot image:** real size and layout of the image and oat files; map it
   through sysd into a suspended host process; private and shared working
   set and private commit after Hello World and after the first frame; which
   image pages ART dirties (must be one contiguous `PAGE_WRITECOPY` range or
   a few); how many image pages a start touches (at ~1.3 µs per page); start
   time with and without the shared image.
2. **GC, with the same app and heap:** the current build (CMC fallback)
   against a read-barrier build (CC): pause times (ART's GC performance
   dump: `-XX:DumpGCPerformanceOnShutdown`), GC throughput on an
   allocation-heavy benchmark, mutator slowdown from read barriers, peak heap
   footprint, and jank in a scrolling benchmark.
3. Confirm that lx answers ART's probes as expected: `userfaultfd` gives
   `ENOSYS`, `mremap(MREMAP_DONTUNMAP)` fails, `/proc/self/cmdline` contains
   the `-Xgc:` option if one is set, and the low-4 GiB heap reservation works
   (needs `MAP_32BIT` or address hints in lx).
4. Repeat round 1 on the reference PC, quiet and on mains power, x64 and
   ARM64.

## Reproduce

```
cd spikes/s2
cargo build --release
target\release\s2.exe boot --procs 24 --appcontainer 2 --mode self      # pagefile section, self-mapping
target\release\s2.exe boot --procs 24 --appcontainer 2 --mode inject    # broker maps into suspended children
target\release\s2.exe boot --procs 24 --appcontainer 2 --backing file   # file-backed section
target\release\s2.exe boot --procs 12 --appcontainer 1 --cow all        # whole view copy-on-write
target\release\s2.exe boot --procs 12 --appcontainer 1 --force-reloc 3  # relocation fallback
target\release\s2.exe boot --procs 12 --appcontainer 1 --prefetch       # PrefetchVirtualMemory before touch
target\release\s2.exe aslr --runs 200                                   # low 4 GiB occupancy
target\release\s2.exe gc --mib 64 --reps 3                              # GC primitives
```

Options: `--size-mib` (default 320), `--base` (default `0x60000000`),
`--dirty-pages` (default 1024), `--threads` and `--compute-ns` for `gc`.
`--appcontainer` grants `ALL APPLICATION PACKAGES` read and execute on the
build output directory and deletes the AppContainer profile at the end. The
file-backed image is written to `%TEMP%\andruna-s2-bootimage.bin`.
