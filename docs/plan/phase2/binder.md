# Phase 2: Binder

Status of `/dev/binder` without a kernel driver (design: [ADR
0025](../../decisions/0025-binder-broker.md)).

## What exists

| Part | Where | State |
| --- | --- | --- |

## Building

```
python aosp/tools/build_host.py aidl        # out/host/<arch>/bin/aidl.exe
python aosp/tools/build_guest.py binder     # after the sysroot, bionic and libcxx steps
```

The binder stage builds, as Android ELF linked against the guest bionic
and libc++: `liblog.so`, `libbase.so`, `libcutils.so` (the subset of
`aosp/modules/libcutils.cmake`), `libutils.so` (all of libutils with
libutils_binder), `libvndksupport.so`, `libapexsupport.so` (Andruna's:
`AApexSupport_loadLibrary` fails, no APEX provides HALs), `libbinder.so`,
`libbinder_ndk.so`, `servicemanager` and the test program
`binder_sm_test`. libbinder's kernel IPC code is unchanged; its sources
and flags follow `Android.bp` (`libbinder_common_defaults`,
`libbinder_android_defaults`, `libbinder_kernel_defaults`; release flags
at their defaults, so no binder observer). The C++ for
`IServiceManager`, `IClientCallback`, `IServiceCallback`,
`ConnectionInfo`, `Service`, `ServiceWithMetadata`, `ServiceDebugInfo`,
`IAccessor` and the five framework interfaces libbinder includes
(`IPccSandboxManagerNative`, `IBinderStatsConsumerService` and its
parcelables, from frameworks/base) is generated by the host `aidl`
(`--lang=cpp`, paths with Windows separators, which aidl matches
textually). The stage is C++23 with `-fno-rtti` (Soong's default) and
`andruna/libcxx_compat.h`. The output is staged in
`out/guest/<arch>/system-root/{bin,lib64}`, the layout sysd uses
(`system/bin/servicemanager` next to sysd, or `ANDRUNA_SYSTEM_ROOT`).

servicemanager is built from its sources unchanged: `Access.cpp`
(SELinux) is replaced by Andruna's implementation of the same class (uid
rules from the broker's identities), and `ServiceManager.cpp` and
`main.cpp` are compiled with `VENDORSERVICEMANAGER`, which leaves out
VINTF manifests and perfetto (Andruna has neither). See ADR 0041.

## Tests

- `cargo test -p andruna-binder`: broker unit tests, guest processes
  simulated in one process: registration with the context manager and
  the caller's identity, the owner's reference protocol, nested calls to
  the waiting thread, one-way ordering per node, death notification and
  `BR_DEAD_REPLY`, clearing a death notification, fd passing and
  `TF_ACCEPT_FDS`, invalid transactions, `BR_SPAWN_LOOPER`, blocking and
  non-blocking reads, thread and process exit with full cleanup,
  concurrent clients (with and without spinning).
- `cargo test -p andruna-binder-device --test transport`: two processes
  (the test binary started twice) use the device through andruna-lx's
  `openat`, `mmap` and `ioctl` with the broker in the parent: identity,
  round trips, fd passing (the client on a private inherited channel),
  death notification, cleanup.
- `cargo test -p andruna-binder-device --test guest`: the same with real
  guest programs, `binder_raw` (C, bionic, `tests/guest/binder_raw.c`)
  under andruna-elf, a context manager and a client in two guest
  processes. Needs `python aosp/tools/build_guest.py binder-tests` and
  andruna-elf; skips without them unless `ANDRUNA_REQUIRE_GUEST=1`.
- `cargo test -p andruna-sysd binder`: sysd's broker refuses processes it
  did not start or allow.
- `cargo test --release -p andruna-sysd --test servicemanager`: sysd's
  broker, servicemanager started by sysd (`Binder::start_servicemanager`,
  which waits for the context manager), and two guest processes with
  libbinder (`aosp/guest/binder/tests/binder_sm_test.cpp`): a service
  (uid 1000) registers `andruna.test.echo`; a client with an app uid
  finds it with `waitForService`, sees `manager`, checks the identity the
  service sees (the client's Windows pid and the uid sysd assigned),
  passes a descriptor to the service and receives one from it, is refused
  `addService` and `listServices` (ADR 0041), times round trips, and gets
  `binderDied` when the service exits. Needs `build_guest.py binder` and
  andruna-elf; skips without them unless `ANDRUNA_REQUIRE_GUEST=1`.
- `cargo test -p andruna-lx registered_devices_have_a_status`: `stat` and
  `access` on a host-registered device path (libbinder checks
  `access("/dev/binder", R_OK)` before using the driver).
- `cargo test -p andruna-binder work_goes_to_the_last_waiting_thread`.

## Round-trip latency

### libbinder through servicemanager

Method: `binder_sm_test client` calls the service (`BBinder::onTransact`,
echo of a byte vector) through `BpBinder::transact`, the full libbinder
path (Parcel, interface token, `IPCThreadState`) in both processes, the
service's libbinder thread pool serving. 5000 timed calls of 100 bytes
and 1250 of 4 KiB after 500 warm-up calls, `CLOCK_MONOTONIC` around each
call, release builds, same machine as below, CPU at 100 % from other
agents' builds, about 5 GB free.

| Wake | Request | p50 us (runs) | p99 us (runs) |
| --- | ---: | --- | --- |
| spin 30 us (default) | 100 B | 7.2 / 6.9 / 8.3 | 50.5 / 40.4 / 102.7 |
| spin 30 us (default) | 4 KiB | 9.2 / 9.6 / 11.2 | 60.1 / 77.3 / 20.1 |
| no spinning | 100 B | 31.4 / 26.6 | 134.1 / 121.5 |
| no spinning | 4 KiB | 35.7 / 29.4 | 151.8 / 114.7 |

The 20 us target holds at p50 with spinning, as with `binder_raw`
(7.4 us in the same session). The first libbinder runs gave p50 42 us:
the broker gave process work to the thread that had waited longest
(FIFO), so with libbinder's thread pool every call woke a sleeping
thread. It now takes the thread that started waiting last, as the kernel
does (`binder_select_thread_ilocked`), which is the one still spinning.
Death notification (service exit to `binderDied` in the client): 2.5 to
10 ms.

### Raw protocol (binder_raw)

Method: `binder_raw client` calls the context manager (`binder_raw
manager`, another guest process) synchronously; the manager echoes the
data. Each call is `BC_TRANSACTION`, the manager's `BC_FREE_BUFFER` and
`BC_REPLY`, the client's `BC_FREE_BUFFER`, through bionic's `ioctl` and
andruna-lx in both guest processes and the broker in a third process.
20000 timed calls after 500 warm-up calls per size, `CLOCK_MONOTONIC`
around each call; release builds; three runs.

Machine: Intel Core Ultra 7 258V (8 cores, no SMT), 32 GB, Windows 11 Pro
build 26300. **Heavily loaded**: about eight other agents were compiling
during the runs and free memory was about 1 GB; tails are dominated by
that and must be re-measured on the reference PC.

| Wake | Request | p50 us (3 runs) | p99 us (3 runs) |
| --- | ---: | --- | --- |
| spin 30 us (default) | 100 B | 7.1 / 6.7 / 7.3 | 32.8 / 22.9 / 21.9 |
| spin 30 us (default) | 4 KiB | 9.5 / 8.9 / 9.9 | 50.1 / 96.6 / 66.1 |
| no spinning (`ANDRUNA_BINDER_SPIN_US=0`) | 100 B | 35.6 / 32.9 / 33.6 | 125.0 / 122.8 / 121.8 |
| no spinning | 4 KiB | 36.4 / 36.9 / 38.4 | 131.2 / 123.6 / 118.1 |

The target ([05-performance](../../spec/05-performance.md): a small round
trip under 20 us) is met with spinning; without spinning it is not met on
this machine. A round trip has six wakes: client to its broker thread,
broker thread to the manager's broker thread (inside sysd), to the
manager, and the same back. S3 measured four wakes on a less loaded
machine (12 us with `SignalObjectAndWait`, 1 us with spinning); removing
the hop between the two broker threads (the sender's broker thread
writing the reply into the receiver's lane directly) is the next step if
the non-spinning case matters.

Spinning is bounded (30 us per wait), only while a lane had a message in
the last 2 ms, and off on machines with fewer than four logical
processors, so idle threads sleep in the kernel.

Death notification: from the manager's exit request to `BR_DEAD_BINDER`
in the client, 2.2 to 4.2 ms, almost all of it process teardown before
the broker's pipe breaks (as in S3).

## Not done

- **Java Binder.** `android.os.ServiceManager.getService` / `addService`
  and a call between two andruna-app processes need framework.jar and
  libandroid_runtime (framework build). Ready on this side: libbinder and
  libbinder_ndk (with libandroid_runtime_lazy) built; the Binder JNI
  sources compile against this libbinder (`binder_jni_check`), and what
  they leave undefined is only libandroid_runtime itself
  (`AndroidRuntime`, `set_dalvik_blockguard_policy`), libnativehelper
  (`AFileDescriptor_*`) and hwbinder's `IPCThreadState::selfOrNull` and
  `getServingStackPointer` (from `binderthreadstate/CallerUtils.h`;
  system/libhwbinder is fetched for its headers). libandroid_runtime
  needs libhwbinder or a small Andruna libhwbinder with those two
  functions (no hwbinder in Andruna: `selfOrNull` is null); a decision
  for the framework build. The Java test program is
  `aosp/guest/binder/java/BinderEchoTest.java` (service; client:
  identity, descriptor, latency, death).
- The guest's own uid: `getuid()` in a guest process is lx's (0), not the
  uid sysd assigned for binder; services use
  `IPCThreadState::getCallingUid()`, which is the broker's.
- ARM64: the binder stage has not been built or run on ARM64.
- CI does not build the guest stages; the servicemanager test skips there.
- Scatter-gather buffers, non-file descriptors in transactions, signal
  interruption of a blocked read, ARM64 measurements (the code builds for
  ARM64; the guest test was run on x64 only).
